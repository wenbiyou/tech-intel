## C · GitHub / 开源生态与开发者工具

### 12. npm 上线 stage-only 令牌
- 摘要：CI 自动化令牌只能暂存版本（`npm stage publish`），真正发布须维护者 2FA 审批，且配置绕过 2FA 无效；直指"发布令牌泄露即投毒"。
- 链接：https://github.blog/changelog/2026-09-18-stage-only-npm-tokens-for-safer-automation
- 对前端架构师的意义：排查所有 npm 发版 CI，把长效 publish token 替换为 stage-only + 人工 2FA 终审。

### 13. GitHub"在场证明"（proof of presence）公开预览
- 摘要：企业可对高风险操作强制交互式重认证/MFA，防会话 cookie 与长效令牌被窃后的破坏；当前仅限使用 Microsoft Entra ID 的 EMU 企业。
- 链接：https://github.blog/changelog/2026-09-24-require-proof-of-presence-for-high-impact-actions/
- 对前端架构师的意义：评估 org 高危操作（分支保护/发布/secret 变更）启用强制重认证；不在 Entra EMU 则纳入 GA 后跟进清单。

### 14. Copilot 代码评审新增个人/企业默认强度配置
- 摘要：Lite/Balanced/GitHub 默认三档，组织与仓库层可覆盖；AI 评审的严格度与成本正式成为可治理策略项。
- 链接：https://github.blog/changelog/2026-09-23-copilot-code-review-more-ways-to-request-and-configure-reviews/
- 对前端架构师的意义：为组织设定统一评审强度默认（如 PR 级 Balanced），避免各仓口径不一与评审成本失控。

### 15. GitHub Enterprise 新增凭据清单导出
- 摘要：SSH key/PAT/OAuth token 全量盘点导出（9/21 更新，与 Grok 进 Copilot 同日发布），面向企业安全审计。
- 链接：https://github.blog/changelog/2026-09-21-grok-4-7-is-now-available-in-github-copilot/
- 对前端架构师的意义：导出一次企业/org 凭据全量清单，清点僵尸 PAT/SSH key，并设为季度例审。
